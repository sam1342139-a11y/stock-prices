# 資料合理性檢查（docs/DATA_CHECKS.md）

> 目的：像 2026-11-23「加權指數被讀成報酬指數」這種錯誤，要能被自動攔下，不讓錯的數字發布出去。

## 什麼時候檢查
GitHub Actions `update-tw-models`（平日 18:30，21:30、23:30 備援）算完所有台股模型輸出、**commit 之前**執行：

```
python3 tw-models/sanity.py check --out /tmp/sanity.json
```

檢查範圍：`tw-models/latest/*.json`（水位燈號、波段、長期、七三組合、33 檔評分）和 `tw-models/paper/latest.json`（模擬資金）。

## 檢查項目與門檻
門檻寫在 `tw-models/sanity.py` 的 `LIMITS`，要改請開申請單。

| # | 項目 | 沒通過的條件 |
|---|---|---|
| 1 | 加權指數 vs 200 日均線 | 偏離超過 ±40%（今天那個錯誤是 +104%） |
| 2 | 加權指數單日漲跌 | 超過 ±12% |
| 3 | 個股單日漲跌 | 超過 ±11%（漲跌幅限制 10%），且當天沒有除權息、減資等還原係數。**同一天 3 檔以上才擋下**；1～2 檔通常是除權息資料還沒補上，只記在「其他提醒」，不擋發布 |
| 4 | 收盤價 | 加權指數或任何個股收盤為 0 或空值 |
| 5 | 外資單日買賣超 | 超過歷史最大值的 2 倍 |
| 6 | 美元兌台幣單日變動 | 超過 3% |
| 7 | 每日資料檔名 | `tw-models/data/daily/` 出現預期外的檔名，例如讀錯檔案 |
| 8 | 輸出檔結構 | 輸出檔不見、不是正確的 JSON，或少了上一版有的欄位（新增欄位不算） |
| 9 | 水位總分 | 不在 0～10 |

櫃買指數目前沒有在系統裡，所以沒有檢查；以後加進來時，會照加權指數的規則一起檢查。

## 沒通過時會發生什麼
1. **不發布新資料**：所有輸出檔改回前一次 commit 的內容（`git checkout HEAD`）。
2. **在 problems 寫明原因**：每個輸出檔的 `problems` 第一筆會是
   `資料檢查未通過（YYYY-MM-DD），本檔維持前一次的資料：<原因；原因…>`
   - 一定以「資料檢查未通過」開頭，讀檔的程式可以直接判斷。
   - 其他欄位，包括 `generated_at_utc`，都維持前一次的值。
3. **開 GitHub issue 通知**：標題是「資料檢查未通過 YYYY-MM-DD」。同一天已經有開著的 issue 就在底下留言，不會重複開。
4. 修正後重跑 `update-tw-models`，檢查通過就恢復發布，`problems` 裡那一筆也會消失。

## 給理專助手（晨間排程）
- 讀任何一個輸出檔時，只要 `problems` 不是空的就跳過，並提醒使用者。資料檢查沒通過時一定會寫進 `problems`，所以不用另外處理。
- 只要看到以「資料檢查未通過」開頭的那一筆，就代表當天的數字**不是新的**。

## 自己在電腦上跑
```
python3 tw-models/sanity.py check --out /tmp/sanity.json   # 結果寫在 /tmp/sanity.json，不改任何檔案
```
